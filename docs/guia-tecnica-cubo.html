Capítulo 1

La idea general del sistema

La plataforma CUBO es un sitio web de dos "caras": una pública que ven los clientes, y una privada que usás vos para administrar todo. Ambas viven en el mismo repositorio de código.

El dato clave para entender todo

La web NO guarda datos en el servidor propio. Todo lo que el sistema "recuerda" (leads, ítems, precios, fotos, configuración) vive en Supabase, que es una base de datos en la nube. Los archivos de código (.html, .css, .js) solo dicen cómo mostrar esa información, no la guardan.

¿Qué es cada tecnología?

TecnologíaPara qué sirveAnalogía
HTMLDefine la estructura: títulos, botones, formularios, tablas. Es el "esqueleto".Como los planos de una casa: define qué va dónde.
CSSDefine el aspecto visual: colores, tipografía, tamaños, espaciado. Es la "pintura y terminaciones".Como el acabado de obra: cómo se ve cada cosa.
JavaScriptDefine el comportamiento: qué pasa cuando hacés clic, cómo se cargan datos, cómo se calculan precios. Es la "instalación eléctrica".Como los sistemas que hacen funcionar la casa: luz, agua, gas.

¿Por qué esta estructura?

Antes, todo el CSS y JavaScript estaba mezclado dentro de los archivos HTML (miles de líneas). Lo separamos en archivos propios para que sea más fácil encontrar y modificar cosas. Cada archivo tiene una responsabilidad clara.

Capítulo 3

Los archivos HTML — la estructura

HTML (HyperText Markup Language) define la estructura del contenido. Pensalo como los planos: dice qué elementos existen y cómo se organizan, pero no dice de qué color son ni qué hacen.

index.html HTML · Público
Es el sitio que ven tus clientes. Contiene todas las secciones de la landing: el hero, los servicios llave en mano, quiénes somos, la galería de obras, cómo funciona, el CTA, y el footer. También tiene el cotizador completo (con sus tres vistas: selección de ítems, formulario de datos, y pantalla de confirmación). Al final del archivo carga index-app.js que le da vida.
admin.html HTML · Privado
Es el panel de administración. Solo accesible con usuario y contraseña de Supabase. Tiene una barra lateral con botones de navegación y un área principal donde se carga el contenido de cada sección: Dashboard, Leads, Ítems, Categorías, Recetas, Catálogo Sismat, Importar Sismat, Fotos Landing, Obras y Configuración. Cada sección es un <div class="page"> que se muestra u oculta según la navegación.

¿Cómo funciona la navegación de una sola página?

Tanto index.html como admin.html son lo que se llama Single Page Applications (SPA): toda la aplicación vive en UN solo archivo HTML. En lugar de cargar páginas nuevas, el JavaScript muestra y oculta secciones según lo que el usuario hace.

Ejemplo en index.html

Todas las secciones empiezan ocultas (section { display: none }). La sección activa tiene la clase act que la hace visible (section.act { display: block }). Cuando el usuario hace clic en "Galería", la función ir('galeria') quita la clase act de la sección actual y se la pone a la de galería.

Capítulo 4

Los archivos CSS — el diseño

CSS (Cascading Style Sheets) controla todo lo visual: colores, tamaños, espaciado, tipografía, animaciones. La "C" de Cascading (en cascada) es importante: cuando hay dos reglas que afectan al mismo elemento, gana la que viene después en el orden de carga.

assets/css/base.css CSS · Base global
Los estilos que se usan en toda la aplicación. Contiene:
  • Las variables de color y tipografía de CUBO (charcoal #484848, blanco, grises)
  • El estilo del nav (barra de navegación superior)
  • Los estilos del cotizador (cards de ítems, sidebar de categorías, resumen)
  • Los modales (captura de leads, alertas, correlaciones)
  • Los formularios y la pantalla de confirmación
  • El footer
assets/css/landing.css CSS · Landing
Sobreescribe y mejora los estilos de la landing con la estética "Vizionare": tipografía Inter 900 con letter-spacing muy negativo, números grandes como elementos decorativos, sin border-radius, sin hover-transforms, grillas de 1px (mosaico). Se carga después de base.css, entonces cualquier clase redefinida acá prevalece. Controla: Hero, Servicios llave en mano, Quiénes somos, Compromiso, Cómo funciona, CTA strip, Galería, y todos sus versiones responsive.
assets/css/admin.css CSS · Admin
Todos los estilos del panel de administración. Un sistema visual completamente separado del sitio público: sidebar oscuro, cards con bordes, tablas, inputs, toggles, modales del admin, badges de estado de leads, y los estilos específicos de cada módulo (Recetas, Catálogo Sismat, Importar Sismat, Fotos Landing).

¿Por qué tres archivos CSS en lugar de uno?

Un solo archivoArchivos separados (lo que tenemos)
Fácil de olvidar qué es de dóndeCada archivo tiene una responsabilidad clara
Si rompo algo en admin, puede afectar la landingLos estilos de admin no afectan la landing (se carga en admin.html solamente)
1000+ líneas en un solo lugarCada archivo tiene 100-300 líneas manejables

Las variables CSS — el "sistema de diseño" de CUBO

Al principio de base.css están definidas las variables. Son como constantes de color que se usan en todo el código. Si mañana querés cambiar el charcoal de #484848 a #333333, lo cambiás en UN solo lugar y afecta a toda la app:

:root {
  --gris-oscuro: #484848; /* El charcoal principal de CUBO */
  --gris-fondo: #F2F2F2; /* Fondo gris claro */
  --blanco: #FFFFFF;
  --tx: #2A2A2A; /* Color del texto principal */
}
Capítulo 5

Los archivos JavaScript — la lógica

JavaScript es el lenguaje que hace que la app sea interactiva: responde a clicks, consulta la base de datos, calcula precios, muestra y oculta elementos. Sin JavaScript la página sería solo texto estático.

Concepto clave: async / await

Consultar la base de datos tarda un tiempo (aunque sea milisegundos). JavaScript tiene que esperar esa respuesta antes de mostrar los datos. Las funciones marcadas con async pueden "pausarse" con await mientras esperan, sin bloquear el resto de la página. Es como decirle al mozo que traiga la comida mientras seguís hablando con los comensales.

assets/js/index-app.js JS · Landing
Toda la lógica del sitio público. Lo primero que hace es conectarse a Supabase. Después contiene:
  • ir(seccion) — navegación entre secciones (inicio, servicios, galería, cotizador)
  • abrirModalLead() / guardarLead() — captura y guardado del formulario de lead
  • cargarDatos() — trae categorías e ítems de Supabase al arrancar la página
  • renderCot() / renderItems() / renderResumen() — dibuja el cotizador
  • agregar() / quitar() — agrega/quita ítems del carrito
  • enviar() — envía el presupuesto final a Supabase
  • cargarGaleria() — trae las obras con fotos y las muestra en la galería
  • cargarCtaNum() — muestra el contador de servicios en el CTA
  • cargarFotosLanding() — carga la foto de Quiénes somos si existe
  • cargarConfiguracion() — trae email, Instagram y teléfono del footer
assets/js/admin-app.js JS · Admin
El núcleo del panel de administración. Maneja login/logout, carga todos los datos al iniciar, y coordina la navegación entre las secciones. Contiene el CRUD (Crear, Leer, Actualizar, Borrar) de: Leads, Ítems y precios, Categorías, Correlaciones, Obras, y Configuración. También tiene el "router": un objeto que mapea cada nombre de sección con la función que la inicializa.
Capítulo 5 (continuación)

Los módulos del admin

El panel admin tiene funcionalidades tan complejas que se dividieron en archivos separados dentro de assets/js/admin/. Cada uno maneja una tab específica.

assets/js/admin/importar-sismat.js JS · Admin
Importación de precios desde Sismat. La extensión de Chrome exporta un JSON con todos los materiales y mano de obra de Sismat. Este módulo lee ese JSON, lo compara con lo que ya hay en la base de datos, muestra un preview del diferencial (cuántos son nuevos, cuántos cambiaron de precio), y cuando confirmás hace el UPSERT masivo en la tabla sismat_catalog. También guarda historial de cambios de precio en precio_historico.
assets/js/admin/catalogo-sismat.js JS · Admin
Gestión del catálogo de 1856 ítems de Sismat. Como son miles de filas, usa paginación del lado del servidor (50 por página) para no cargar todo de golpe. Te permite filtrar por tipo, categoría, o visibilidad, y para cada ítem podés: activarlo/desactivarlo en el cotizador, sobrescribir el nombre con uno más consumer-friendly, y asignarlo a una categoría CUBO. Los cambios se guardan en la tabla sismat_catalog_overrides (sin tocar la fuente de verdad).
assets/js/admin/recetas.js JS · Admin
Gestión de recetas del cotizador. Una receta es un servicio compuesto (ej: "M² de contrapiso") que combina múltiples materiales y mano de obra de Sismat con sus cantidades por unidad. Este módulo te permite crear/editar recetas, agregar componentes buscando en el catálogo Sismat, y ver el precio calculado en tiempo real (suma de costos × markup de categoría × ajuste adicional). Las recetas son lo que eventualmente verán los clientes en el cotizador.
assets/js/admin/fotos-landing.js JS · Admin
Gestión de fotos de la landing. Tiene dos partes: los "slots fijos" (la foto de Quiénes somos) y la galería de obras. Para cada uno, permite arrastrar una imagen o seleccionarla desde el explorador de archivos. Antes de subirla, la comprime automáticamente usando Canvas (máximo 1600px de ancho, calidad 85%) para no desperdiciar espacio ni velocidad. Guarda la foto en el bucket landing-fotos de Supabase Storage y la URL pública en la base de datos.
Capítulo 6

Supabase — la base de datos

Supabase es una plataforma que te da una base de datos PostgreSQL en la nube más herramientas adicionales, todo accesible desde el browser sin necesitar un servidor propio.

Las tablas de la base de datos

TablaQué guarda
leadsCada persona que usó el cotizador: nombre, email, teléfono, zona, ítems cotizados, estado (nuevo/contactado/cerrado).
categoriasLos grupos del cotizador (Albañilería, Pintura, Electricidad...) con su markup de precio.
itemsLos servicios individuales del cotizador actual (sistema legado, convive con recetas).
correlacionesReglas "si el cliente elige X, sugerir Y". Ej: si elige pisos, sugerir preparación del sustrato.
obrasLas obras de la galería: título, zona, tipo, URL de imagen.
configuracionDatos de contacto del footer: email, Instagram, teléfono, zona de trabajo.
sismat_catalogLos ~1856 materiales y mano de obra de Sismat con sus precios (fuente de verdad de costos).
sismat_catalog_overridesLas personalizaciones de CUBO sobre el catálogo: nombre consumer, visibilidad, categoría asignada.
recetasLos servicios compuestos del cotizador nuevo (ej: "M² de contrapiso").
receta_componentesLos ingredientes de cada receta: qué material/MO usa y en qué cantidad por unidad.
precio_historicoLog de cambios de precio en Sismat: qué ítem subió/bajó cuánto y cuándo.
landing_mediaFotos de slots fijos de la landing (Quiénes somos, etc.).

¿Cómo se conecta el código con Supabase?

Al principio de cada archivo JS que necesita datos hay estas dos líneas:

const SUPABASE_URL = 'https://swxkfibuvbazvrclzxlx.supabase.co';
const SUPABASE_KEY = 'sb_publishable_...';
const sb = supabase.createClient(SUPABASE_URL, SUPABASE_KEY);

sb es el "cliente" de Supabase. Una vez creado, todas las consultas se hacen a través de él. Ejemplos reales del código:

// Traer todas las categorías activas:
const { data } = await sb.from('categorias').select('*').eq('activo', true);

// Guardar un lead nuevo:
await sb.from('leads').insert({ nombre, email, telefono });

// Actualizar el estado de un lead:
await sb.from('leads').update({ estado: 'contactado' }).eq('id', leadId);

RLS — Row Level Security

Cada tabla en Supabase tiene políticas de seguridad que controlan quién puede hacer qué. La configuración de CUBO es:

  • Anónimo (cualquier visitante): puede LEER categorías, ítems, recetas, configuración. No puede modificar nada.
  • Autenticado (vos en el admin): puede leer, crear, modificar y borrar todo.

Esto es lo que hace que el cotizador funcione sin login, pero el admin requiera contraseña.

Capítulo 7

Supabase Storage — las fotos

Además de la base de datos, Supabase tiene un servicio de almacenamiento de archivos (Storage). Es como un Google Drive, pero accesible desde código.

El bucket "landing-fotos"

Un bucket es como una carpeta principal. Creamos el bucket landing-fotos con acceso público: cualquier visitante puede VER las imágenes, pero solo el admin puede subir o borrar.

Organización de archivos dentro del bucket
landing-fotos/
├── slots/
│ └── quienes-1748123456789.jpg ← Foto de Quiénes somos
└── obras/
    ├── a1b2c3d4.jpg ← Foto de la obra con ese ID
    └── e5f6g7h8.jpg

El flujo de subida de una foto

1
El usuario selecciona o arrastra un archivo
El browser captura el archivo como un objeto File.
2
flComprimirImagen() — compresión automática
La función dibuja la imagen en un Canvas HTML invisible, la redimensiona a máximo 1600px de ancho, y la convierte a JPG al 85% de calidad. Esto reduce una foto de 8MB a ~300KB sin pérdida visible de calidad.
3
_flSubir() — upload a Supabase Storage
La imagen comprimida se sube al bucket. Supabase devuelve la URL pública permanente (algo como https://swx...supabase.co/storage/v1/object/public/landing-fotos/obras/id.jpg).
4
Guardar la URL en la base de datos
La URL pública se guarda en obras.imagen_url (o landing_media.url para slots fijos). También se guarda el path del archivo en imagen_storage_path para poder borrarlo después.
5
La landing la carga automáticamente
La función cargarGaleria() consulta las obras con imagen_url, las muestra en la grilla. No hay que hacer nada más.
Capítulo 8

Las migraciones SQL

Una "migración" es un archivo con instrucciones SQL para modificar la estructura de la base de datos. Son como los planos de remodelación: dicen qué tablas crear, qué columnas agregar, qué permisos dar.

migrations/001_sismat_catalog.sql SQL · Ejecutado
Crea toda la estructura del sistema de precios nuevo: tablas sismat_catalog, sismat_catalog_overrides, recetas, receta_componentes y precio_historico. También agrega la columna markup_porcentaje a la tabla categorias existente.
migrations/002_landing_media.sql SQL · Pendiente
Crea el bucket de Storage landing-fotos con sus políticas de acceso, agrega la columna imagen_storage_path a la tabla obras, y crea la tabla landing_media para los slots fijos de fotos de la landing.
¿Por qué guardar las migraciones como archivos?

Si la base de datos se borra o migrás a otro proyecto de Supabase, tenés los pasos exactos para recrearla. Es como tener los planos de la obra guardados.

¿Qué es SQL?

SQL (Structured Query Language) es el lenguaje para hablar con bases de datos. Las instrucciones más comunes:

Capítulo 9

El flujo completo de precios

Este es el corazón del sistema: cómo el precio de Sismat se convierte en el precio que ve el cliente final.

1
Sismat publica precios de mayorista
Sismat es el proveedor. Sus precios son precios de costo para CUBO.
2
La extensión de Chrome extrae los precios
La extensión (cubo-sismat-extension/) scrapea el sitio de Sismat con tu sesión activa y exporta un JSON con todos los materiales y MO.
3
Admin: Importar Sismat
Subís el JSON al admin. El sistema compara con los precios anteriores, muestra diferencias, y al confirmar hace UPSERT en sismat_catalog.
4
Admin: Catálogo Sismat — personalizás
Marcás qué ítems son visibles, les ponés nombres consumer-friendly, y los asignás a categorías CUBO con su markup correspondiente.
5
Admin: Recetas — armás los servicios
Creás una receta "M² de contrapiso" y le agregás: 0.18 bolsas de cemento + 0.022 m³ de arena + mano de obra de colocación. El precio se calcula solo.
La fórmula del precio final

Base = Σ (precio_sismat_de_cada_componente × cantidad)
Con markup = Base × (1 + markup_categoría / 100)
Final = Con markup × (1 + ajuste_receta / 100)

Ejemplo: cemento $8.500 × 0.18 bolsas = $1.530. Si la categoría albañilería tiene 35% de markup: $1.530 × 1.35 = $2.066. Si hay un ajuste adicional del 10%: $2.066 × 1.10 = $2.273 / m².

6
El cotizador muestra el precio al cliente
El cliente entra al sitio, selecciona "M² de contrapiso", ingresa 25 m², ve el precio orientativo, completa sus datos y envía el lead.
Capítulo 10

La extensión de Chrome

La carpeta cubo-sismat-extension/ contiene una extensión de Chrome que automatiza la extracción de precios de Sismat. Sin ella, tendrías que copiar cada precio a mano.

¿Cómo funciona una extensión de Chrome?

Una extensión tiene acceso al contenido de las páginas que visitás. Cuando instalás la extensión y abrís el sitio de Sismat, el código JavaScript de la extensión puede leer los datos de esa página (materiales, precios, categorías) y exportarlos.

Seguridad importante

La extensión usa TU sesión activa en Sismat (las cookies de tu navegador). Nunca guarda tu usuario ni contraseña. Es como si la extensión "viera la pantalla" mientras estás logueado.

Archivo de la extensiónQué hace
manifest.jsonDefine la extensión: nombre, versión, permisos, y qué scripts ejecutar en qué páginas.
content.jsEl script principal. Se ejecuta dentro del sitio de Sismat, llama a la API interna de Sismat, procesa los datos, y genera el JSON para exportar.
popup.htmlLa pequeña ventana que aparece cuando hacés clic en el ícono de la extensión. Tiene el botón "Exportar JSON".
Capítulo 11

Conceptos de desarrollo web explicados

¿Qué es un "UPSERT"?

Un UPSERT es una operación de base de datos que combina INSERT y UPDATE: si el registro no existe, lo crea; si ya existe, lo actualiza. En el proyecto se usa para actualizar precios sin borrar los anteriores, y para guardar overrides del catálogo.

// Si ya existe un override para ese sismat_id, lo actualiza.
// Si no existe, lo crea.
await sb.from('sismat_catalog_overrides')
  .upsert({ sismat_id: 123, nombre_cubo: 'Cemento Loma Negra' }, { onConflict: 'sismat_id' });

¿Qué es una "función asíncrona"?

En JavaScript, cuando pedís datos a una base de datos o servidor, el programa no se puede "congelar" esperando la respuesta (eso bloquearía toda la página). Las funciones async/await permiten esperar sin bloquear:

// Versión "congelada" (MAL — el navegador se traba):
const datos = obtenerDatos(); // espera bloqueando todo

// Versión async/await (BIEN — el navegador sigue respondiendo):
const datos = await obtenerDatos(); // espera sin bloquear

¿Qué significa "paginación del lado del servidor"?

El catálogo de Sismat tiene 1856 ítems. Si intentás cargar todos de una vez, el browser recibe 1856 filas de datos, crea 1856 elementos HTML, y se pone lento. La paginación del servidor le dice a Supabase "dame solo los ítems del 50 al 100" usando .range(50, 99). El browser solo maneja 50 filas por vez.

¿Qué es el "DOM"?

El DOM (Document Object Model) es la representación en memoria del HTML de la página. Cuando el JavaScript hace document.getElementById('items-area').innerHTML = '...', está reescribiendo una sección del HTML en vivo, sin recargar la página. Así funciona todo el cotizador y el admin.

¿Qué es una API?

Una API (Application Programming Interface) es como una "ventanilla" de datos. Supabase expone una API automáticamente para cada tabla: podés pedirle datos, mandarle datos nuevos, actualizarlos o borrarlos con llamadas HTTP. La librería de Supabase que usamos (supabase-js) traduce el código JavaScript en esas llamadas HTTP automáticamente.
